# Методическая библиотека

Отдельный поисковый индекс книг о подготовке, написании, оформлении и защите
диссертации, а также о чтении, аргументации и выступлении. Книги дают советы
авторов и не являются научными доказательствами реестра: их фрагменты не
подтверждают тезисы диссертации и не попадают в `search_knowledge`.

Индекс статей не перестраивается и не читается: у библиотеки свой каталог
состояния `../../.knowledge/library/` (`active.json`, поколения, кэш эмбеддингов,
`writer.lock`), метка Neo4j `Library` с русским fulltext-анализатором и коллекции
Qdrant `aspa_library_g_*`. Шлюз эмбеддингов и модель те же (GigaChat
`EmbeddingsGigaR`, 2560).

## Состав

[Каталог](catalog.json) — канон: библиографические данные только из самих
файлов, SHA-256 оригиналов, происхождение и параметры разбора. Пустые поля
объяснены в `field_resolution`; ничего не дописано по памяти.

## Запуск

Из корня `research`, при запущенном контуре знаний (см. [инструкцию](../README.md)):

```powershell
uv run --frozen researchctl library prepare --download   # нормализация + report.json
uv run --frozen researchctl library build --offline      # проверка проекции без провайдеров
uv run --frozen researchctl library build                # граф + эмбеддинги, продолжает с checkpoint
uv run --frozen researchctl library check
uv run --frozen researchctl library evaluate             # recall@5, цель ≥ 0.8
uv run --frozen researchctl library publish <generation>
```

`status`, `books`, `search "<запрос>" [--book B004]`, `passage <chunk_id>` и
`rollback` служат для диагностики. `.doc` разбирается через `antiword`
(`RESEARCH_ANTIWORD` или Git for Windows); Docker-образу он не нужен, потому что
нормализация выполняется на хосте. `RESEARCH_LIBRARY_DIR` переопределяет каталог
состояния.

## Доступ агента

MCP `aspa-research` предоставляет `library_status`, `list_library_books`,
`search_library(query, book_ids, mode, limit)` и `get_library_passage(chunk_id,
context)`, ресурсы — `research://library-catalog` и `research://library-guide`.
Ответ содержит `citation`, `section_path`, `pages` (если есть), точные смещения и
фактический `mode`: `hybrid`, `neo4j_lexical`, `dense+fallback_lexical` или
`library_lexical_fallback`. Резервный лексический режим не называть гибридным.
`citation` строится по текущему каталогу; в проекции и заголовках эмбеддингов остаётся
прежняя формула (`index_citation`), чтобы не менять поколение. Фрагмент через несколько
разворотов получает один диапазон: `98–99` … `100–101` → `pages: "98–101"`.

Цитируя совет, указывайте книгу, раздел и страницу. Флаг `fragment` в ответе
означает ознакомительный фрагмент: отсутствие ответа тогда не значит, что темы
нет в книге. Перед дословной цитатой получите отрывок через `get_library_passage` —
он сверяется с нормализованным текстом.

## Разбор и известные ограничения

- Главы и разделы — из структуры файла (FB2, HTML), печатного оглавления
  (B007, B008, B009) или строгой последовательности номеров `III. 1. 2.` (B001,
  где конвертер слил главы в сплошной текст; заголовок — первые слова раздела).
- Переносы склеиваются, только если слитная форма встречается в той же книге;
  настоящие составные слова (`научно-популярный`) сохраняются.
- Фрагмент — до 700 оценочных токенов (~2,8 тыс. знаков) с перекрытием ~80, не
  пересекает крупные разделы; короткие разделы объединяются с соседними.
- PDF: колонтитулы, водяные знаки (строка на большинстве листов) и повторные
  листы удаляются; номер страницы берётся из колонтитула, только если он идёт по
  порядку. B006 свёрстан разворотами, локатор — разворот (`20–21`). В OCR-книгах
  (`join_split_words`) пробел внутри слова убирается, если слитная форма есть в
  книге, а одна из частей отдельно не встречается.
- B005 и B009 — OCR: возможны ошибки в латинице, таблицах и схемах. В B010 нет
  96 рисунков и формул. Именной указатель и реклама B002, оглавления B007,
  B009 и англоязычное оглавление B010 исключены.

## Перенос на другой сервер

Git хранит рецепт сборки (каталог, код, проверки), но не тексты книг и не
эмбеддинги. Переносимый снимок их дополняет:

```powershell
uv run --frozen researchctl library export               # .knowledge/snapshots/library-<gen>.zip
# на новом сервере, после git clone и запуска контура:
uv run --frozen researchctl library restore <архив.zip>  # проверка SHA-256 каждого файла
uv run --frozen researchctl library build                # граф и векторы из кэша, без вызовов GigaChat
uv run --frozen researchctl library publish <generation> # generation совпадает с snapshot.json
```

В архиве — оригиналы, нормализованные тексты, отчёт подготовки и кэш
эмбеддингов; секретов, `active.json` и состояния бэкендов в нём нет. Трекаемый
[snapshot.json](snapshot.json) фиксирует SHA-256 архива и поколение, которое из
него собирается; `restore` предупреждает, если архив или каталог отличаются.
Архив содержит полные тексты книг, поэтому хранится вне публичного репозитория:
в приватном `deneal123/AICSC_research_snapshots` (Git LFS), клонированном в
`.knowledge/snapshots/` — туда же `export` пишет новые архивы.

## Добавление книги

1. Положить файл в `docs/Текста/` (или указать URL), посчитать SHA-256.
2. Добавить запись `B0NN` в каталог: данные только из файла, пустые поля — с
   `field_resolution`, при необходимости `options` (`exclude_sections`, `toc`,
   `inline_headings`, `max_heading_level`).
3. `library prepare`, просмотреть `report.json` и выборку текста; добавить
   2–3 запроса в `evaluation.json`.
4. `library build` → `check` → `evaluate` → `publish`; затем обновить манифест
   релиза (`python scripts/check_release.py --write`).

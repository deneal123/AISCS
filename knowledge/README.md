# База знаний диссертации

Канон находится в `../data/`; здесь — реестр текстов, схема извлечения,
фиксированный набор поисковых проверок и итоговый отчёт. Производные данные
хранятся в игнорируемой `../.knowledge/`, временные — в `../.work/`.

## Запуск

[Итог проверки](validation-report.md), [40 запросов](evaluation.json) и
[результаты поиска](evaluation-results.json) относятся к локальному проверочному набору.

1. В `.knowledge/runtime.env` задайте `RESEARCH_NEO4J_PASSWORD`,
   `RESEARCH_EMBEDDING_KEY` и действующие `AGENTS__GIGACHAT_*` настройки.
   `AGENTS__GIGACHAT_CA_BUNDLE=/run/certs/gigachat-ca.pem`; TLS включён.
   Этот файл игнорируется Git. Пароли не передаются в аргументах команды.
2. Запустите `docker compose --env-file .knowledge/runtime.env -f compose.knowledge.yaml
   --profile knowledge up -d --build`.
3. Выполните `python -m service.cli knowledge prepare --candidates .work/knowledge-candidates.json`.
   Каждый кандидат содержит `source_id`, `path`, `primary_url`; наличие ID в имени
   файла не подтверждает идентичность. `--download` разрешает первичные маршруты.
4. Загрузите настройки из закрытого env-файла в окружение процесса, затем выполните
   `python -m service.cli knowledge build`. После проверки кандидата —
   `python -m service.cli knowledge publish <generation>`.

`build --offline` проверяет локальную проекцию без провайдеров. Её можно явно
опубликовать с `--allow-offline`; это **лексический режим**, без проверенного
векторного индекса. Команды `status`, `check`, `evaluate`, `rollback`, `search`
и `graph` дают диагностику и управляют поколениями. Docker-проект изолирован
от GPTHub; его коллекции не используются.

## Доступ агента

После перезапуска существующего research MCP доступны четыре новых операции.
Локальные CLI/MCP читают только ключ шлюза и пароль графа из `.knowledge/runtime.env`;
явные переменные окружения имеют приоритет. Секреты в Codex config добавлять не требуется.

По умолчанию RRF объединяет совпадения по источнику и показывает лучший доказательный
фрагмент в `matched_evidence`. Фильтр `source_id` раскрывает несколько фрагментов одной работы.
Канонические DOI/URL, статус проверки и ограничения возвращаются вместе с каждым совпадением.

Существующий research MCP предоставляет `search_knowledge`, `graph_context`,
`get_evidence`, `knowledge_status`. HTTP аналоги находятся под `/v1/knowledge/`.
Порт исследовательского контура — 8093; Neo4j Browser — 7476; Bolt — 7689;
Qdrant — 6335; шлюз — 8092. Порты привязаны к localhost.

Возвращайте вместе с найденным материалом источник, локатор, статус проверки,
ограничение и допустимый вывод. `include_unreviewed=true` предназначен для
проверки предложений, а не для обоснования научных выводов. Ранжирование поиска
не ранжирует новизну. Недоступность dense-поиска явно указана в ответе.

## Извлечение через Pi

Для локальных копий `retrieved_at` означает включение файла в этот корпус;
дата исходной сетевой загрузки без сохранённых метаданных неизвестна. `version`
обозначает версию содержимого по хешу; версию публикации берите из канонической карточки.

Pi читает только зарегистрированный документ. Его предложения соответствуют
`extraction.schema.json`; точная цитата проверяется по хешу текста и смещениям.
Итоговый `extractions.jsonl` содержит решения основного агента. Принятие требует
записи reviewer/date/rationale; существование цитаты само по себе не подтверждает
научный смысл связи. Названия без точного идентификатора остаются привязаны к
документу. Worker-материалы записываются в `.work/pi-workers/<run>/<task>/`.

Сохраняются G0_REVISE, saturation=false и ограничения действующего контракта.

## Готовность и восстановление

`docker compose --env-file .knowledge/runtime.env -f compose.knowledge.yaml --profile knowledge ps`
показывает состояние четырёх healthcheck. Шлюз проверяет локальную готовность;
доступность внешних эмбеддингов подтверждается реальным поиском, а не healthcheck.
Для обычного запуска добавьте `up -d --build --wait`; собственные тома не удаляйте.

После перезапуска контейнеров опубликованное поколение читается из `.knowledge/active.json`.
`knowledge build` повторно использует кэш и продолжает прерванную загрузку;
`knowledge check` проверяет тексты, ID и локаторы. Публикация — только после успешной
проверки, возврат к предыдущему поколению — `knowledge rollback`.

`knowledge_status` различает `published_corpus` и `prepared_corpus`; прежнее поле `corpus`
обозначает опубликованный корпус. Для старого поколения без снимка реестра это поле
равно `null`, а не текущему черновому покрытию. `unreviewed_canonical_edges` и
`unreviewed_pi_edges` показывают разные источники неподтверждённых связей.
Отклонённые материалы доступны только в явном режиме проверки вместе с их статусом.

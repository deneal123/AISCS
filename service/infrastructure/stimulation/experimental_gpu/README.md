# Экспериментальные компоненты GPU

`packing.py` проверяет и объединяет деревья в пакет. Совместная работа с
ядром сверена с NEURON на трёх морфологиях и искусственных событиях;
подключение к основному исполнителю остаётся открытым.

`hines_kernel.py` содержит экспериментальное CUDA-ядро для пакетных деревьев;
оно не подключено к исполнителю сервиса. Импортированное ядро проверено на
трёх морфологиях относительно NEURON; обработка всех краевых событий и сетевой
расчёт остаются открытыми. Для запуска отдельно необходим Numba с поддержкой CUDA.
В прототипе шаг жёстко задан как 0,025 мс, таблица кинетики ограничена
диапазоном −100…100 мВ, параметры ворот пишутся для первых трёх клеток пакета.
Токи и напряжения записываются для всех клеток; корректность за пределами
проверенных режимов и динамическое взаимодействие сети не установлены.
Флаг выхода напряжения за диапазон таблицы для каждой клетки проверен на GPU
на нормальном, завышенном и нечисловом значениях. `validation.py` содержит
проверку результатов после синхронизации; подключение её к исполнителю и сверка
полного сетевого сценария ещё не завершены. Изменённое ядро повторно сверено
на трёх морфологиях; флаги диапазона в этом расчёте не сработали.

`tree_geometry.py` строит дерево для уточнённых кабельных сегментов и отвергает
циклы, несвязные графы и некорректные сопротивления. На топологии SWC 51132
с синтетическими сопротивлениями построенное дерево побайтно совпало с
прототипом. С реальными сопротивлениями и 37 событиями результат проверен
против NEURON на этой клетке; подключение к исполнителю остаётся открытым.

`batching.py` группирует морфологии по числу сегментов, ограничивая размер
пакета и долю заполнителей. Возвращаются исходные индексы клеток; бюджет
задаётся вызывающим кодом с учётом всех буферов. Планировщик пока не подключён
к решателю и сам по себе не резервирует память GPU.

`tree_levels.py` строит уровни дерева и группы дочерних узлов по родителю.
Один исполнитель группы может суммировать вклады без конкурирующих записей;
между уровнями требуется синхронизация. CUDA-решатель к этому плану пока не
подключён.

Модуль `events.py` проверяет и переводит события существующего планировщика
на индексы явно заданной сетки. Он не запускает решатель и не подключён к API.
Точные концы отростков требуют отдельной проверенной политики дискретизации.

`waveform.py` подготавливает значения кусочно-линейного стимула в серединах
шагов по исходным узлам, включая изломы внутри шага. Для совпадающих узлов
явно выбран последний уровень. Это подготовка входа для экспериментов:
семантика на разрывах и соответствие NEURON проверены лишь в случаях ниже;
к решателю и API функция не подключена.

Один пассивный компартмент NEURON 9.0.1 проверен для излома внутри шага и
двух разрывов: ток совпал с выборкой середины шага до 3,24×10⁻¹³ нА.
Полная проверка HH, GPU и других временных протоколов остаётся открытой.
На одном активном HH-компартменте два способа подачи трёх импульсов с
фронтами вне сетки дали в NEURON разность напряжения до 4,98×10⁻¹³ мВ;
сравнение с GPU-решателем и сетью ещё не выполнено.

Прототипы численного решателя и их проверки находятся в игнорируемой `.work/`
суперпроекта. Результаты и незакрытые ограничения перечислены в `generator/TODO.md`.
Они не являются проверкой приложения, полной сети или биологической модели.

Запись на лету сворачивает токи сегментов в сигнал конкретной пары контактов.
Восстановить из одного такого сигнала токи всех сегментов и пересчитать сигнал
для произвольно переставленных контактов в общем случае нельзя. Для повторной
регистрации нужен архив токов с проверенной геометрией либо новый расчёт;
существующий `recording/current_archive.py` предназначен для архива выбранных
клеток, а не для физической записи всей сети.

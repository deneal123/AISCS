# Работа с текстом диссертации

Начать с [README](README.md), [реестра](data/text.json) и нужного пункта [TODO](TODO.md). Тема, цель и шесть задач берутся из ИПР; текущий текст содержит первую редакцию главы 1 и каркас последующих глав. Сборка не подтверждает научный результат.

## Выбор исходника

- Текст и формулы: `document/chapters/`, `document/frontmatter/`, `document/backmatter/`.
- Общие параметры и реквизиты: `document/config/`; главный файл — `document/dissertation.tex`.
- Источники: `data/bibliography.json`, `data/chapter1-evidence.json`, локальный `data/research-snapshot/snapshot.json`.
- Правила оформления и история проверок: [инструкция документа](document/README.md), [аудит](docs/formatting-audit.md). Для диссертации ГОСТ имеет приоритет перед дипломным образцом.

## Научная редакция

Проверять существенное утверждение по первичному локатору и доступному контексту. Сохранять границы частичного текста. Для новых сведений сначала обновить локальные доказательные привязки; прямое чтение изменяемого соседнего research не заменяет импортированного снимка. Ноцицепцию, субъективную боль, ECAP и клинический исход не отождествлять. Польза переноса параметров Drosophila остаётся проверяемой гипотезой.

Не менять согласованные задачи и не писать новые результаты в рамках простой правки оформления. По мере выполнения исследования заменять перспективные описания только фактическими результатами с данными, контролями и неопределённостью. Пример AgentsSwarm не является источником результатов диссертации.

## Сборка и проверка

Использовать `textctl validate`, затем `textctl build TEXT-001 --profile draft`. Изменения библиографии воспроизводить `python scripts/build_bibliography.py`; утверждения главы 1 проверять `python scripts/audit_chapter1.py`. Полный набор — `scripts/check.ps1` или `make check`.

После изменения вёрстки открыть PDF и проверить затронутые страницы, оглавление, подписи и ссылки. Успешная сборка обновляет предварительный PDF; `build --check`, ошибка и отказ release сохраняют прежний. Выпуск требует подтверждённых реквизитов и approvals; не выставлять их для обхода проверки.

## Сохранение работы

Рабочие загрузки и промежуточные результаты размещать в игнорируемой `.work/`, сборку — в `build/`. Источники, принятые рисунки и PDF для просмотра сохранять в их рабочих каталогах. Архивы и локальный снимок не редактировать вручную. TODO менять по конкретному выполненному критерию, связывая его с доказательством; историю держать в существующем аудите.

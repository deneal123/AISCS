# Контракты генератора и платформы

Статус: спецификация первой версии, не описание действующих API. Схемы будут реализованы в коде и проверяться на совместимость, как существующие контракты сайдкаров. Версия HTTP-контракта, версия научной модели и версия образа — разные поля.

## Опыт и попытка

**Опыт (`run`)** — неизменяемая после принятия конфигурация. Повтор с изменением параметров создаёт новый run с `parent_run_id`. **Попытка (`attempt`)** — конкретное исполнение опыта. Транспортный повтор не создаёт новый опыт; перезапуск прерванного вычисления создаёт следующую попытку с тем же seed и собственной историей.

| Группа | Обязательное содержание |
|---|---|
| Идентичность | run ID, владелец, backend job ID, contract version, дата; необязательный parent run ID |
| Модель | ID/версия пресета и каждого адаптера, версия кода, хеши геометрии/коннектома/весов |
| Условия | воздействие, параметры состояния, длительность, разогрев, dt, схема записи, электрод/референс, шум |
| Воспроизводимость | отдельные seeds динамики, воздействия и шума; точность/устройство/численный режим; хеш полной конфигурации |
| Происхождение | organism/stage/sex, версии данных, первичные локаторы, допущения и допустимый вывод |
| Исполнение | attempt ID, исполнитель, номер попытки, право публикации, heartbeat, состояние и причина завершения |

Владелец определяется сессией backend, а не принимается из тела браузерного запроса. Пути и URL входных файлов заменяются разрешёнными идентификаторами зарегистрированных ресурсов.

Размещение электрода через сцену сохраняет якорь на визуальном меше отдельно от физического контакта: хеш ассета, область, преобразование координат и его версию, физические координаты/геометрию E1 и REF, единицы и проводящую среду. Подробные правила — в [сценарии размещения](09-scene-interaction.md). Без преобразования и поддерживаемого оператора точка остаётся аннотацией. Изменение электрода принятого опыта создаёт дочерний run; геометрический предпросмотр не является опубликованной записью.

Долговечные записи: существующее задание типа SIMULATION; связанная `SimulationRun` с конфигурацией; `SimulationAttempt` с назначением исполнителя и правом публикации; связи `SimulationArtifact` с существующими пользовательскими файлами. Конкретные SQL-имена фиксируются миграцией; это новые предметные сущности в существующей БД, а не второй реестр общих заданий.

## Состояния

Доменные состояния: `queued → preparing → running → publishing → completed`. Из нетерминального состояния возможны `cancelling → cancelled`, `failed` и `interrupted`. Прерванный запуск не считается завершённым и не обещает продолжение с промежуточного шага без отдельной поддержки движка.

Общие состояния существующего задания отображаются так: queued — NEW; preparing/running/publishing/cancelling — PROCESSING; completed — SUCCESS; failed/interrupted/cancelled — FAILURE с отдельной доменной причиной. UI симулятора использует доменное состояние и показывает отмену отдельно от ошибки. Старые API сохраняют прежний контракт состояний.

Терминальную запись может завершить только актуальная попытка, сохранившая право публикации. Повтор события не повторяет запись файла или смену состояния. Отмена и финализация сериализуются транзакционно: после подтверждённой отмены SUCCESS не возникает.

## Публичные интерфейсы backend

| Метод и маршрут | Назначение |
|---|---|
| `GET /api/simulations/v1/catalog` | Доступные пресеты, адаптеры, параметры/единицы, состояние готовности |
| `POST /api/simulations/v1/runs` | Создать опыт по конфигурации и ключу идемпотентности; вернуть run/job ID |
| `GET /api/simulations/v1/runs` | Список собственных опытов с пагинацией |
| `GET /api/simulations/v1/runs/{run_id}` | Состояние, конфигурация, попытки, метрики и ссылки на зарегистрированные файлы |
| `POST /api/simulations/v1/runs/{run_id}/cancel` | Зафиксировать намерение остановки; не выдавать его за завершённую отмену |
| `GET /api/simulations/v1/runs/{run_id}/artifacts` | Опись доступных файлов и их состояние публикации |
| WebSocket `/api/simulations/v1/runs/{run_id}/events` | Авторизованный поток с индивидуальным курсором и снимком для восстановления |

Скачивание использует существующий `GET /api/service/files/v1/{file_id}/download`. Новая предметная API не требует chat/thread/dataset ID. Для WebSocket переиспользуются auth и Redis-примитивы, но не общий consumer group, распределяющий события между вкладками вместо доставки каждой.

Входы и ответы ограничиваются типизированными схемами. Неизвестная модель, конфликт ключа идемпотентности, несовместимая схема и отсутствие входных данных имеют разные машинные причины. Внутренние исключения, пути, ключи объектов и секреты не попадают в пользовательские ошибки.

## Приватный интерфейс generator

| Метод и маршрут | Назначение |
|---|---|
| `GET /health` | Процесс, версия сервиса и контракта |
| `GET /ready` | Импорт/инициализация выбранного движка, доступность обязательных входов; занятость отдельно от исправности |
| `GET /capabilities` | Реестр реализованных адаптеров и совместимых контрактов |
| `POST /v1/executions` | Принять конкретную attempt ID, конфигурацию и разрешённые входы; повтор возвращает существующее исполнение |
| `GET /v1/executions/{attempt_id}` | Состояние исполнения, последнее событие и доступность манифеста |
| `GET /v1/executions/{attempt_id}/events` | NDJSON с курсором; backend проверяет и передаёт события в свой поток |
| `POST /v1/executions/{attempt_id}/cancel` | Остановить дочерний процесс данной попытки |
| `GET /v1/executions/{attempt_id}/manifest` | Полная опись результатов с размерами и хешами |
| `GET /v1/executions/{attempt_id}/artifacts/{artifact_id}` | Поток байтов зарегистрированного файла, не произвольный путь |
| `POST /v1/executions/{attempt_id}/ack` | Подтверждение долговечной публикации; разрешение очистить scratch |

Вычислительные маршруты требуют служебной авторизации. Прямого браузерного доступа нет. Повторное подтверждение очистки безопасно. После перезапуска без сохранившейся попытки сервис отвечает «попытка неизвестна», а backend фиксирует interruption; новая попытка не выдаётся за продолжение предыдущей.

## Адаптер и событие

Декларация адаптера: `id`, `version`, поддерживаемые типы входа/выхода, схема параметров, единицы, сетка времени, требования к ресурсам, режим воспроизводимости, ограничения. Передача между стадиями сохраняет координатную систему и единицы. Voxel, микрометр, миллисекунда и tick не взаимозаменяемы; преобразование должно быть записано явно.

Событие содержит `schema_version`, `run_id`, `attempt_id`, `sequence`, `kind`, время регистрации и при наличии `simulation_time_ms`. Виды: состояние, стадия, численный прогресс, ограниченный блок превью, предупреждение, подготовленный артефакт, итог. Доля готовности передаётся только при известном знаменателе; heartbeat не изображает выполненную работу.

События превью могут быть прорежены, полные результаты — нет. Результат распознавания несёт версию классификатора, границы анализируемого окна и предсказанный класс. Уверенность выводится только при наличии соответствующего определённого показателя; произвольный процент не генерируется.

## Артефакт

Манифест результата содержит ID опыта/попытки, хеш конфигурации, происхождение модели, ограничения и список файлов. Для файла обязательны ID, безопасное имя, роль, MIME, размер, SHA-256, версия схемы; для массива — размерность, единицы, временная ось и идентификаторы каналов. Отсутствие необязательного файла имеет явную причину.

Базовые роли: configuration, provenance, signals, neural_events, model_states, stimulus_ground_truth, predictions, metrics, figure, report. Полные табличные данные — Parquet; CSV — экспорт для человека; конфигурации/метрики/манифест — JSON; рисунки — SVG/PNG. PDF-отчёт дополнительный, его отсутствие не блокирует корректный численный экспорт.

Файл истинных условий отделён от признаков классификатора. Ни имя файла, ни ID сценария, ни параметры воздействия не становятся признаками. Модель распознавания фиксируется до проверки отложенных реализаций.

Численный результат обязательного протокола включает хотя бы конфигурацию, происхождение, полный электродный сигнал, единицы/каналы и манифест. Для сценария распознавания дополнительно обязательны предсказания и метрики проверки. Превью и график не заменяют исходную запись.

# Порядок интеграции и проверки

Все этапы ниже — предстоящие. Готовность документации не закрывает ни одного runtime-критерия.

## Этапы

| Этап | Работы | Условие перехода |
|---|---|---|
| I0. Зафиксировать исходное состояние | HEAD/status каждого проекта, gitlinks, входные файлы, тома и конфигурации без секретов; сохранить пользовательскую работу | Понятно, какие приложения восстановлены локально и что получит независимый checkout |
| I1. Восстановить платформенный контур | Копия инфраструктуры GPTHub: build/run/sync_env, backend/frontend/PostgreSQL/Redis, отдельные beat и воркеры; MinIO dev и внешний S3 prod. Подробности в [решении 12](12-platform-infrastructure.md) | Реальный вход, тестовое собственное задание и файл работают; ничего не удалено из GPTHub |
| I2. Ввести домен симуляций | Аддитивные миграции, SIMULATION, собственные входы и состояния, outbox/попытки, права и профиль приложения | Контрактные тесты и интеграционные проверки БД проходят без численного движка |
| I3. Создать generator | Изолированная сборка, NEURON/LFPy, пресет локальной цепи, оператор электрода, CLI/HTTP, экспорт | Автономный численный пример даёт проверяемые токи и потенциал, а не нарисованную трассу |
| I4. Соединить выполнение и хранение | Celery-worker, приватный клиент, события, остановка, streaming публикация и очистка после ack | Полный опыт воспроизводится после обновления страницы и доступен владельцу |
| I5. Подготовить демонстрацию | Страница, 3D, графики, состояния модели, классификатор и сравнение опытов | Критерии [пятничной демонстрации](05-demo-2026-10-30.md) проверены |
| I6. Добавлять вспомогательные функции | DuckDB, документы/workspace, помощник, ссылки research | Каждая возможность включается независимо; отказ помощника не прерывает численный опыт |

Профили Compose: базовая платформа; simulation; дополнительные analysis/assistant. Первоначально используется Local storage в отдельном долговечном томе; MinIO включается как альтернативный явно выбранный provider и проверяется отдельно. Для существующих данных сохраняется их прежний provider: запуск демо не переключает имеющееся хранилище.

Для первой изолированной установки использовать собственные имена Compose-проекта, сетей, томов и свободные host-порты. Не останавливать стенды GPTHub/Alter, не подключать их рабочие тома как тестовые. Секреты остаются в штатных env/secret-механизмах; документация не содержит значений.

Периодические задачи включать по назначению: обслуживание файлов и попыток симуляции — да; платёжные и чатовые задания — только в соответствующем профиле. Научный сайдкар не запускает отдельный beat.

## Изменения существующего кода при реализации

1. Ввести отдельный путь создания SIMULATION с общим заданием и доменными записями, не расширять старый file-only запрос бесконтрольным словарём.
2. Добавить тип в коде и PostgreSQL enum аддитивной миграцией. Проверить обработку типа старыми сериализаторами; менять режим профиля только после обновления совместимых сервисов.
3. Существующие чатовые захваты, биллинг и отмену оставить в чатовой области. Общие транзакционные/transport примитивы переиспользовать; типизированная симуляция не должна случайно попасть под чатовый сборщик устаревших заданий.
4. Унифицировать Celery-конфигурацию. Старое имя переменной допускается только как документированный алиас; конфликт значений — ошибка запуска, а не случайный выбор.
5. Исправить проверку владельца при отказе БД в используемом WebSocket-коде. Потоки симуляции читаются с независимым курсором каждой вкладки.
6. Добавить чтение несекретного application profile, домашний маршрут и API-политику. Регрессии gpthub должны проверяться отдельно от simulation.
7. В проверках контрактов/окружения зарегистрировать generator как сосед backend. Не добавлять его в настройки agents до появления агентного инструмента, которому это действительно необходимо.
8. Дополнить инструкции и Makefile только командами реально существующих файлов. При миграции gitlinks не перезаписывать восстановленные пользовательские checkout.

## Матрица приёмки

| ID | Сценарий | Ожидаемое доказательство |
|---|---|---|
| A01 | Автономный generator без backend | CLI и HTTP используют одно ядро, фиксированные входы и сопоставимый экспорт |
| A02 | Корректность оператора | Аналитический тест одиночного источника с референсом, знак/единицы, допустимое расстояние; проверка dt и конечности значений |
| A03 | Сквозной запуск | Браузер → API → очередь → реальный solver → сохранённые файлы → чтение браузером; общий run ID |
| A04 | Повтор доставки и потерянный ответ | Один логический опыт; известная попытка запрашивается повторно, а не запускается второй раз |
| A05 | Отмена в очереди, расчёте и публикации | Процесс остановлен, терминальное состояние согласовано, поздний ответ не становится SUCCESS |
| A06 | Перезапуск worker/generator | Явный interruption/recovery; новый attempt ID при повторе, без ложного продолжения |
| A07 | Redis/брокер недоступен | Нет вымышленного прогресса; долговечные результаты читаются после восстановления; намерение отправки не теряется |
| A08 | Разрыв WS, две вкладки | Обе получают полный ряд событий, повтор не дублирует график; обрезанная история восстанавливается снимком |
| A09 | Чужие run/file/attempt ID, отказ БД | Доступ закрыт; отсутствие проверки не трактуется как разрешение |
| A10 | Ошибка хранения, неверный хеш, неполный манифест | Нет completed; обязательный артефакт не заменяется пустым файлом; повтор регистрации идемпотентен |
| A11 | Local и реальный MinIO | Одинаковая логика владения/хешей/скачивания; mock не закрывает проверку MinIO |
| A12 | Кэш | Изменения model/data/seed/оператора инвалидируют нужные стадии; смена электрода переиспользует только допустимые входы |
| A13 | Очистка | Удаляется scratch подтверждённой попытки; активные файлы, опубликованные артефакты и чужие контейнеры сохранены |
| A14 | Профили приложения | Прямые старые URL, preload, post-login и API согласованы; gpthub по-прежнему работает при своём профиле |
| A15 | Контракт/ресурсы | Несовместимая версия или отсутствующая модель отклоняется; занятость не означает готовый результат; длительность/RAM измерены |
| A16 | Научный экспорт | Полные временные оси, каналы, единицы, источники, seeds, версии и SHA-256 разрешаются независимо от UI |

Ресурсные результаты включают время постановки/начала/расчёта/публикации, задержку появления данных на экране, peak RAM процесса и контейнера, VRAM при наличии GPU, объём записи. В отчёте сохраняются машина, образ и конфигурация. Числа не назначаются заранее как якобы измеренные.

## Проверки и откат

Ruff/pytest выполняются из проекта-владельца; frontend — его lint/build/unit и браузерные сценарии. Контрактные тесты запускаются без научных зависимостей; реальные NEURON/LFPy и Docker-интеграция — отдельно. Сбой optional-сайдкара проверяется явно.

Проверки документов: относительные ссылки, UTF-8/LF, отсутствие временных данных в tracked-путях, сохранность защищённых входов и `git diff --check`. Секреты и научные оригиналы не попадают в тестовые фикстуры.

Откат интерфейса — переключение профиля и остановка только созданных simulation-процессов после урегулирования активных попыток. Новые таблицы и файлы сохраняются. Старый бинарник допускается лишь после проверки совместимости с аддитивным типом SIMULATION; разрушительный downgrade БД не является штатным откатом.

Для приёмки сохранять команды, версии, результат, логи и хеши артефактов. Сообщение «готово» требует реального A03; зелёные healthcheck или mock-тесты его не заменяют.

# Реализация и проверенные результаты

Срез: 28 октября 2026 года. Это живой отчёт текущей реализации; открытые критерии ведутся в [TODO](TODO.md). Ранние разделы сохраняют результаты промежуточных этапов; текущая сводка и итоговые проверки приведены ниже.

Текущий стенд использует FlyBody, отдельный NEURON/LFPy-исполнитель и MinIO,
собранный из закреплённых исходников. Дополнительная приёмка событий и отказов
содержит 34 успешные сетевые проверки. Локальное окно и синхронное сравнение
проверены на двух размерах экрана. Открыты
общий демонстрационный аудит и регистрация будущего выпуска; научная применимость
модели остаётся отдельным предметом проверки.

## Что переиспользуется по итогам REPORT.md

Пересмотрены все 32 раздела отчёта с сопоставлением реестра и assessment. Успешный запуск не подтверждает биологическую достоверность. Ни один из проверенных SIM не предоставляет готовый физический оператор требуемой локальной внеклеточной регистрации.

Для первой реализации выбрана сборка компонентов:

- **SIM-020 FlyGym:** первоначальная геометрия из 39 STL NeuroMechFly, rigging и нейтральной позы, 69 деталей после сборки. Она сохранена для прежних зарегистрированных опытов; отображение сглажено без изменения исходных треугольников выбора области. Это визуальный контекст, а не подтверждённая морфология нейронной модели.
- **SIM-003 / FlyBody:** после замечания пользователя основным выбран FlyBody — та же модель тела, которую использует Infinite Sugar. Переносятся 85 визуальных частей, 272550 треугольников, нормали, материалы и иерархия шести лап. XML побайтово совпал с первичным MuJoCo Menagerie; модель имеет собственную Apache-2.0. Приложение Infinite Sugar, его авторские двигательные сценарии и лицензия на них не подменяются лицензией модели. Происхождение и преобразования перечислены в [реестре ассета](../../../frontend/public/assets/simulator/flybody/README.md).
- **SIM-009/029:** проверенные подходы к слоям, камере, выбору области и прозрачности. Сцена использует существующий Three.js и собственный адаптер данных; исследовательский браузерный движок не запускается вторым владельцем серверного опыта.
- **SIM-011/012:** кандидаты подготовки нейронной геометрии, пока без переноса неподтверждённых клеточных параметров. Первая численная модель использует явно авторскую геометрию.
- **SIM-001/006/015/020/021/023/024/031/033:** контрольные реализации, экспорт и будущие адаптеры. Выявленные несогласованные часы, reset и ограничения данных не переносятся как штатное поведение.

Подробная карта всех кандидатов находится в [документе 10](10-simulation-reuse.md). Публикация на GitHub сама по себе не означает разрешительную лицензию: [правило GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository). Локальный исследовательский охват сохраняет все сайдкары; происхождение и условия конкретных переносимых файлов учитываются отдельно.

## Автономное численное ядро

Реализована цепь из шести многокомпартментных клеток NEURON с generic Hodgkin–Huxley-параметрами. Вход задаётся сенсорному звену модели, мембранные токи записываются в нА; LFPy/lfpykit преобразует токи в потенциал однородного проводника, из записи E1 вычитается REF. Спайки экспортируются отдельно.

В Linux Docker прошли шесть тестов: аналитическая проверка точечного источника и единиц, обращение знака при смене референса, запрет контакта внутри источника, точный повтор seed, изменение записи при переносе контакта, нулевой вход и контроль шага времени. Модель не реконструирует весь коннектом и не является проверенной моделью субъективной боли или человеческого ECAP.

## Первая проверка распознавания

Зафиксированы 30 конфигураций/seeds, по три условия в каждой: всего 90 реализаций. Разбиение по целым группам: train 54, validation 18, test 18. Признаки — RMS, размах и средний квадрат электродной записи после 20 мс. Стандартизация обучена только на train, регуляризация выбрана на validation; test не использовался для выбора.

| Показатель | Результат |
|---|---|
| Validation balanced accuracy | 72,2% |
| Test balanced accuracy | 66,7% |
| Постоянное предсказание | 33,3% |
| Контроль с переставленными train-метками | 38,9% |
| Независимых тестовых групп | 6, по три условия |

Порядок классов: отсутствует, сильное, слабое. Матрица test: `[[5,0,1],[0,6,0],[5,0,1]]`. Слабое воздействие часто смешивается с отсутствующим; этот недостаток сохраняется в отчёте и интерфейсе. Результат относится только к синтетической локальной модели. Биологическая валидация, калибровка вероятностей и обобщение при смене электрода/шума не подтверждены.

Метрики, группировка и компактные коэффициенты демонстрационного классификатора сохранены в `generator/validation/demo-v1/`; сырые записи и рабочие файлы — в `.work/generator-implementation/evaluation/`. Улучшение слабого класса требует отдельного протокола и нового отложенного набора; менять генератор для улучшения уже просмотренного test нельзя.

## Повторная проверка: кэш, восстановление и FlyBody

В Linux Docker пройдены **19 тестов generator** (`generator-tests-flybody.xml`):
оператор, воспроизводимость, строгий контракт, численная геометрия, кэш, события
компартментов, остановка и прерывание, а также независимая поддержка новых FlyBody
и прежних FlyGym-контекстов. Исходный хеш конфигурации без контекста сохранён.

Для кэша проверены точное совпадение мембранных токов при перемещении E1 и изменение
сигнала регистрации, смена seed/версии движка, повреждённый файл и отключённый кэш.
Ключ включает код, параметры динамики и версии; положение пассивных регистрирующих
контактов не меняет расчёт динамики. Размер восстанавливаемого кэша ограничен 128 МиБ.

В отдельном `aspa-acceptance` выполнены реальные fault-проверки
(`runtime-faults.json`, `passed=true`): повторная доставка, перезапуск воркера с
продолжением известной попытки, прерывание исполнителя с новой попыткой, недоступный
Redis при сохранённом результате, восстановление outbox и отмена при приостановленном
MinIO во время публикации. Скачанные файлы сверены независимо по manifest и SHA-256.
Первый сценарий недоступности хранилища блокировал подготовку раньше расчёта; он
сохранён отдельно и не называется тестом отмены публикации. После испытаний удалены
только контейнеры и тома собственного `aspa-acceptance`; основной стек и research
сохранены.

В браузере для FlyBody проверены 85 частей, 6 корней лап, воспроизведение рассчитанных
событий, циклический повтор, прозрачность, запрет контакта внутри источника и Escape
(`fly-visual-result.json`). В `tests/simulator` пройдены **3 live-проверки**, один
дублирующий расчёт для второго размера намеренно пропущен: 1366×768, 1920×1080 и
сохранение выбранного треугольника через очередь, manifest и повторное открытие.
Предпочтение уменьшенного движения учитывается при автозапуске;
явное воспроизведение остаётся доступным. Учёт движения по шести корням — условная
авторская визуализация, не результат расчёта мышц или подтверждение ноцицепции.

События отдельных сегментов берутся из фактических пересечений порога напряжения.
Грудной сегмент и система регистрации неподвижны; движение лап не меняет геометрию
LFPy. Геометрия FlyBody экспортируется один раз через MuJoCo 3.3.7 в миллиметры;
крылья используют заданные в первичном XML углы покоя пружин. В браузере проверяются
SHA-256 метаданных и двоичного буфера. Научный оператор и классификатор для замены
модели тела не перенастраивались.

Разбор новых концептов и очередь визуальных улучшений вынесены в
[документ 13](13-visual-model-and-concepts.md). Общая шкала входа/ответа/записи
проверена отдельно, как описано ниже. Локальное окно и сравнение сцен остаются
отдельными критериями, а не следствием смены 3D-модели.

Повторный экспорт FlyBody побайтово совпал для геометрии, регистрации, provenance
и лицензии (`flybody-export-validation.json`). Проверены индексы всех 85 частей,
конечность координат, единичные нормали и совпадение регистрации frontend/executor.
Ruff, ESLint, 7 целевых frontend-тестов, production-сборка frontend и проверка
канонических UI-владельцев пройдены. Итоговая сверка: 2760 защищённых файлов без
изменений, 101 относительная ссылка, UTF-8/LF и `git diff --check` без замечаний.

Удаление временного окружения экспортёра автоматическая проверка отклонила с
причиной `blocked by policy`; оно и промежуточные копии оставлены в игнорируемой
`.work/generator-implementation/`. Это не часть поставляемых зависимостей.

Первая попытка холодной сборки MinIO из закреплённого исходного commit завершилась
ошибкой передачи Git/TLS. Тогда локальный образ не заменялся, RUN-15 оставался
открытым. Последующая сборка по проверяемому архиву описана в заключительном разделе.

## Общая временная шкала и журнал входа

В численном движке добавлена запись назначенных входных событий ExpSyn: клетка,
время и вес в микросименсах. Этот журнал включён в preview и численные массивы
states.npz; число обязательных файлов осталось равным десяти. Метаданные кэша
защищены контрольной суммой вместе с журналом; изменение записи события вызывает
повторный расчёт вместо использования изменённых данных.

Параметры и порядок генерации случайных времён не изменены. До правки скачаны
состояния существовавшего опыта. После правки восемь массивов — время, напряжения,
мембранные токи, геометрия, диаметры и идентификаторы — точно совпали по значениям
(`input-journal-numerical-regression.json`). Это проверка регрессии конкретной
реализации, не новая биологическая валидация.

Разворачиваемая полоса «Вход и ответ» показывает четыре дорожки с общим курсором:
назначенный вход Δg, спайки шести клеток, условное отклонение корней лап в градусах
и E1−REF в микровольтах. Оранжевые точки в сцене соответствуют входным событиям;
зелёный цвет — рассчитанным пороговым пересечениям. Старый отсутствующий журнал
подписан явно и отличается от зарегистрированного нулевого входа. При изменении
любого параметра черновика прежняя запись остаётся подписанной как сохранённый
опыт. График кэширует дорожки и обновляет курсор, не перестраивая их каждый кадр.

Пройдены **20 тестов generator**, **9 целевых frontend-тестов**, Ruff и ESLint.
Live UI: **3 passed**, один дублирующий расчёт намеренно пропущен. Новый опыт
прошёл через очередь и MinIO; проверено совпадение часов сцены/графика и подсветка
клетки в момент из сохранённого журнала. Отдельно проверена успешная сборка frontend.

Измерения одного локального опыта: 200 мс модельного времени, 8001 отсчёт, 18 входных
событий и 84 соматических события; solver — 0,175 с, peak RSS дочернего процесса —
230,7 МиБ. От создания до последнего обновления опубликованной записи прошло 8,07 с.
Пять повторных чтений заняли 46,8–48,9 мс; в предшествующей пятёрке наблюдалось
единичное чтение 2442,8 мс, причина не установлена. Повтор не отменяет этот выброс.

В headless Edge 156 на RTX 3060 Laptop, 1920×1080, измерена частота вызовов
requestAnimationFrame: около 101 кадров/с с четырьмя дорожками и 104 в компактном
режиме, по 120 интервалам; p95 интервала 18,1 и 18,2 мс соответственно. Загрузка до
готового меша — 1,32 с. Это локальная диагностическая выборка, не нагрузочный тест,
не верхняя граница задержки и не гарантия частоты кадров другого браузера.
Основания: `timeline-runtime.json`, `scene-performance.json`, `ui-tests.json`.

## Локальное хранилище, отмена и проверка владельца

В отдельном `aspa-acceptance-local` пройден сквозной расчёт с реальным файловым
хранилищем. После остановки его MinIO продолжились публикация нового опыта и
скачивание десяти файлов, проверенных по SHA-256. Это отдельная проверка local;
она не подменяет ранее пройденную проверку MinIO.

Подтверждены отказ анонимному клиенту и 404 другому владельцу для опыта, списка
файлов, manifest и конкретного файла. После остановки только тестового PostgreSQL
те же операции вернули серверную ошибку, а не сохранённые данные без проверки
владельца. При отмене в очереди попытка не создаётся; последующая доставка не
запускает уже отменённую работу. Проверены отмена работающего исполнителя и
сохранение терминального состояния. Основание: `local-storage-acceptance.json`.

Команды и тестовые overlays теперь находятся в `docker/docker-compose.simulation.acceptance*.yaml`
и `scripts/simulation_local_acceptance.py`. Их следует применять только к отдельным
`aspa-acceptance[-suffix]` с собственными томами; скрипт проверяет Compose-владельца
перед управлением контейнером. Основной контур и research не останавливались.

## FlyBody, локальное окно и синхронное сравнение

Вместо дальнейшего сглаживания упрощённых STL используется именно FlyBody из
закреплённого SIM-003: 85 частей, 272550 треугольников, исходные материалы и
нормали. Неподвижная грудь сохраняет систему координат регистрации; условно
двигаются шесть корней лап. Полный двигательный контроллер SIM-003 не переносился.
Повторный экспорт побайтово воспроизвёл ассет; SIM-003 остался чистым на commit
`fdbbd866b203a709a164970b0a8996108edd57a5`.

Локальное окно — только приём отображения, с полупрозрачным контуром груди.
Выбор точки использует исходную поверхность, а не визуальную прорезь. Отдельное
приближение показывает цепь и E1/REF. Тепловое поле и внешняя электрическая
стимуляция не изображаются как рассчитанные величины.

Во вкладке сравнения A — закреплённая запись, B — выбранная. Два вида имеют
общие камеру, время и физическую амплитудную шкалу; вход, спайки и условное
движение в нижних дорожках относятся к B. Проверяются фактические временные оси,
единицы, версии ядра/оператора и зарегистрированная рамка. Несовместимые данные
не интерполируются автоматически. URL восстанавливает пару без нового задания;
недоступная A не лишает пользователя доступной B.

Браузерный прогон: **5 passed**, один намеренно пропущенный повтор того же
численного сценария. Проверены 1366×768 и 1920×1080, камера мышью и клавиатурой,
локальное окно, три условия воздействия, адаптация, смена E1 при тех же токах,
восстановление пары, несовместимые данные и запрет запуска неприменённой позиции.
Один новый опыт действительно прошёл очередь и публикацию, включая исходный
якорь, SHA-256 и WebSocket. Живые сценарии: `frontend/tests/simulator/`.

При размонтировании обнаружена ошибка `TransformControls.dispose()` закреплённого
Three.js r169: метод обращается к отсутствующему у `Controls` обходу `traverse`.
Адаптер явно отключает обработчики и контакт; геометрию и материалы освобождает
владелец сцены. Это устранённый дефект, а не списанная на HMR случайность.
Основание — [исходник r169](https://github.com/mrdoob/three.js/blob/r169/examples/jsm/controls/TransformControls.js).

На RTX 3060 Laptop в headless Edge 156, 1920×1080, по 180 интервалам rAF:
последний повтор: одна сцена — около **52 кадров/с**, p95 30,4 мс;
две — около **46 кадров/с**, p95 30,6 мс. Готовность меша после перехода —
1,10 и 1,05 с; кэш ассетов мог
быть прогрет, это не холодный запуск и не момент первого GPU-кадра.
JS heap — около 107,9 и 86,3 МиБ, не полный RAM/VRAM процесса. После паузы
неизменные сцены за 400 мс не выполнили ни одной дополнительной отрисовки.

ранний замер до оптимизации сохранён отдельно и не заменён утверждением о росте FPS.

Артефакты: `ui-tests.json`, `comparison-fixtures.json`,

Доступные без `.work` [снимки реализации](visuals/runtime/README.md) имеют отдельный

Примеры не скрывают ошибки распознавания при отсутствии воздействия и смещении

коэффициентов. Общий демонстрационный аудит и самостоятельное получение всех

## Приёмка переходов, показа и восстановления графики

Дополнены сценарии, которых не покрывала предыдущая проверка одной сцены.
Полноэкранный режим действительно использует API браузера, скрывает платформенную
шапку и список опытов, оставляя время, запись и управление. Выход возвращает
прежнюю компоновку. Переход от размещения к параметрам или другой вкладке
отменяет неприменённую позицию; повторное нажатие «Электроды» не меняет точку
возврата. Применённая позиция остаётся черновиком следующего расчёта.

Список показывает условие воздействия и время создания, загружает более старые
записи через серверный `next_offset`. Ошибка чтения не стирает уже показанные
опыты; повтор относится к той же странице. Файлы автоматически соответствуют
выбранному опыту; запоздавший ответ отменённого чтения не заполняет другой опыт.
Это проверено отдельными тестами гонок, а не только осмотром интерфейса.

В браузере вызвана настоящая потеря `WEBGL_lose_context`. При ней доступны

Кнопка восстановления создаёт новый графический контекст без нового задания.
Подсказка наведения различает зарегистрированную поверхность и область только
для просмотра; выбор не проходит сквозь ближайшую видимую часть тела.

# Схемы работы симуляции AISCS

Папка содержит схемы Mermaid, объясняющие, как устроена симуляция целиком: от нажатия
кнопки во фронтенде до файлов результата на диске. Схемы разделены по уровням, потому
что «симулятор» здесь — это четыре разные вещи с разной физикой.

| Файл | О чём | Уровень |
| --- | --- | --- |
| [01-obshchaya-arhitektura.md](01-obshchaya-arhitektura.md) | Сквозной путь запроса: фронтенд → backend → Celery → генератор → GPU → артефакты | система |
| [02-prostoy-raschet-lif.md](02-prostoy-raschet-lif.md) | Быстрый расчёт: поле по SWC и LIF-прокси всей сети ЦНС | сеть, без кабелей |
| [03-podrobnyy-raschet-fragment.md](03-podrobnyy-raschet-fragment.md) | Подробный расчёт: фрагмент до 256 клеток, HH-кабели, обратная связь, затем прокси всей сети | клетки + сеть |

## Как читать

* Прямоугольник — шаг или компонент. Ромб — проверка, которая может отказать.
* Сплошная стрелка — данные текут в эту сторону. Пунктир — ссылка на идентификатор,
  а не поток данных.
* Пометки «измерено» означают цифру из прогона на этой машине: 166 700 клеток,
  RTX 3060 Laptop 6 ГБ, docker VM 8,2 ГБ.
* Схемы не являются спецификацией API: точные контракты лежат в
  R:/Aspa/generator/service/domain/contracts/ и R:/Aspa/backend/service/services/simulations/.

## Как отрисовать

Каждый файл — обычный Markdown с блоками mermaid; GitHub, GitLab, Obsidian и VS Code
(Markdown Preview Mermaid Support) рисуют их сами. Локально, все схемы одного файла
сразу в набор SVG рядом с исходником:

    npx -y @mermaid-js/mermaid-cli -i 01-obshchaya-arhitektura.md -o 01-obshchaya-arhitektura.md -e svg -a out
    npx -y @mermaid-js/mermaid-cli -i 05-yadro-kletki-i-gpu.md -o 05-yadro-kletki-i-gpu.md -e png -a out --size 2400

Проверено на mermaid-cli 11: все 37 блоков разбираются без ошибок и рисуются.
Готовых картинок в репозитории нет намеренно: схемы должны меняться вместе с кодом.

## Главное в одном абзаце

Фронтенд отправляет запрос в backend, backend проверяет манифест и ставит задачу в
Celery, воркер вызывает генератор по HTTP. Генератор либо считает поле и гоняет
LIF-сеть по всей ЦНС (быстрый расчёт), либо поднимает изолированный процесс, который
читает подготовленную геометрию, восстанавливает клетки, решает уравнения
Ходжкина—Хаксли на GPU окнами и выдаёт пересечения порога. События складываются в
расписание синаптических доставок и подаются на следующий проход — так замыкается
обратная связь. Результат публикуется после того, как расписание перестало меняться,
вместе с контрольной ветвью (нулевой стимул) и с хешами всех файлов; если сходимости
не было, публикация помечается явно (`cycle_detected`, `iteration_limit`), и в ней
сказано, что последнее сетевое расписание к записи не применено.

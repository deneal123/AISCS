# Память GPTHub: провайдеры и подтверждения

Обновлено 22.10.2026. Обычный самостоятельный MemOS сохраняет прежний режим;
интеграция GPTHub включается `MOS_MULTIPROVIDER_ENABLED=true`. Для совместимости
существующего dev-контейнера распознаётся также штатный внутренний шлюз `agents:/v1`.
Явное `false` отключает это распознавание.
Прежний самостоятельный `backup_client` эмбеддера больше не допускается без изоляции
пространства: такой конфиг даёт явную ошибку, а не скрытое смешивание векторов.

## Владельцы ответственности

- Backend хранит структурированные факты в PostgreSQL, собирает и сжимает историю.
- Agents выбирает разрешённую модель через общий provider admission. Профили
  `gpthub-memory` и `gpthub-memory-embedding` не привязаны к RouterAI.
- MemOS хранит текст/связи в Neo4j и векторы в Qdrant. Не выдаёт успех записи без
  обратного чтения узла и фактического вектора.

## Переключение моделей

Явный отказ модели до исполнения допускает ограниченный выбор резерва в том же запросе.
При таймауте/неизвестном ACK запрос не переигрывается: модель получает временный cooldown,
следующее самостоятельное обращение выбирает доступный резерв. Неизвестная стоимость
не объявляется нулевой.

Шлюз возвращает `gpthub_embedding_space` — digest провайдера, точного model ID и размерности.
`SpaceVector` переносит эту идентичность в metadata; сериализация её не теряет.
`SpaceAwareQdrantVecDB` адресует отдельные коллекции по space и размерности. Одинаковый
размер векторов не даёт права смешивать модели. Тексты и граф при переключении не стираются;
старые векторы могут временно перестать участвовать в поиске. Автоматической переиндексации
старых текстов в этом срезе нет. PostgreSQL-факты продолжают работать независимо от MemOS.

Сводки backend записываются синхронно в fast-режиме: повторная платная экстракция уже
подготовленного резюме не запускается. Ответ `indexed=true` подтверждается чтением графа
и индекса; при частичной записи возвращается неподтверждённый исход, не ложный успех.

## Проверки

Особенности нативного GigaChat usage нормализует его адаптер в agents: документированный
расход каждого элемента embeddings суммируется один раз, без выдуманного нулевого usage.

Регрессии: `tests/gpthub/test_memory_spaces.py`, `tests/embedders/test_universal_api.py`,
`tests/vec_dbs/test_qdrant.py`, `tests/llms/test_openai.py`,
`tests/reranker/test_local_rerankers.py`, `tests/gpthub/test_russian_prompts.py`.

Платная приёмка запускается отдельно: `scripts/memory_acceptance_server.py` обслуживает
только один явно заданный синтетический куб, без фонового scheduler. Его модельный транспорт
проходит через ограничитель `backend/scripts/memory_acceptance`, остальные сервисы настоящие.
Подробные результаты и границы — в корневом `docs/MEMORY_STABILITY_ACCEPTANCE.md`.

# Generator

Изолированный численный сайдкар AISCS: полный зарегистрированный граф MaleCNS,
его локальная биофизическая проекция, мембранные токи и запись E1−REF через LFPy.
Прежняя локальная цепь сохраняется отдельным пресетом. Пользователи, очередь,
права доступа и постоянное хранилище принадлежат backend.

## Структура

| Каталог | Ответственность |
|---|---|
| `service/domain/` | Динамика, размещение контактов, признаки и порты адаптеров |
| `service/application/` | Генерация записи и независимое разбиение реализации классификатора |
| `service/infrastructure/` | NEURON, LFPy, экспорт, изолированный процесс и распознавание |
| `service/presentation/` | HTTP и CLI |
| `service/settings/` | Настройки, приватный токен и пути |
| `service/main.py` | Сборка зависимостей и фабрика приложения |
| `validation/demo-v1/` | Зафиксированные параметры классификатора, разбиение и результаты проверки |
| `validation/male-cns-v1/` | Отдельный замороженный протокол полной сети, 480 записей, ошибки и контрольные суммы |
| `tools/connectome/` | Закреплённый сборщик зарегистрированного графа из первичных файлов |
| `docker/`, `tests/` | Linux-сборка и численные/контрактные проверки |

Пакет использует собственный `uv.lock` и Linux Python 3.12. Имя `service` совпадает
с другими сайдкарами: запускать команды из этого проекта, не объединять Python paths.

## Запуск

Основной контур запускается из суперпроекта через `docker/build.sh --dev` и
`docker/run.sh --dev`. Приватный токен создаёт общий `docker/sync_env.py`.

Автономно в Linux:

```sh
uv sync --frozen
uv run generatorctl catalog
uv run generatorctl run --stimulus strong --seed 1 --output .work/example
uv run pytest -q
uv run ruff check service tests
```

Для независимой Linux-проверки из этого каталога:

```sh
docker build -f docker/Dockerfile --target test -t aiscs-generator-test:0.1.0 .
docker run --rm aiscs-generator-test:0.1.0
docker build -f docker/Dockerfile --target runtime -t aiscs-generator:0.1.0 .
```

Рабочий образ не содержит тестов, pytest и Ruff. Тестовый target использует то же
ядро и lock-файл; временные результаты записываются в `/work` или `/tmp`.

HTTP: `/health`, авторизованные `/ready`, `/capabilities`, `/v1/validate`,
`/v1/executions` и операции status/cancel/manifest/artifacts/ack/discard.
Передать `Authorization: Bearer <GENERATOR_TOKEN>`; секрет не включать в конфигурацию
опыта. Повтор ID с другой конфигурацией отклоняется. `ack` очищает промежуточные
файлы только после подтверждения хеша конфигурации; receipt сохраняется.

## Область применимости

Авторская цепь из шести клеток и общие HH-параметры не являются проверенной моделью
ноцицепции Drosophila. Геометрия мухи в frontend задаёт визуальный контекст.
Физический оператор предполагает бесконечный однородный изотропный проводник.
Токи — нА, время — мс, координаты — мкм, потенциал — мкВ.

Классификатор прежней локальной демонстрации различает три воздействия по сигналу.
Отложенная balanced accuracy — 2/3; слабое воздействие распознаётся недостаточно
устойчиво. Это вычислительная проверка на синтетических реализациях, без проверки
на животных или людях. Результаты и ошибки сохранены в `validation/demo-v1/`.

Пресет `male-cns-hybrid-v1` рассчитывает 166 700 нейронов и 25 582 938 связей;
линии рисунка используют LOD. Входы головы и ног подтверждены аннотациями, вход
брюшка недоступен. Периферические пути схематичны. Запись относится к шести HH-
источникам проекции, а не ко всей ЦНС. Отдельное распознавание полной модели имеет
balanced accuracy 71,875% на 96 отложенных записях из 32 конфигураций; полнота
слабого класса — 53,125%. Общий классификатор без области дал 72,917%:
преимущество регионального варианта не показано. Результаты, матрицы ошибок,
диапазоны применимости и повторная проверка — в `validation/male-cns-v1/`.
Данные не входят в образ/Git; отсутствие набора не подменяется локальной
моделью при запросе полного пресета. Команда `generatorctl connectome-verify`
проверяет все зарегистрированные хеши. Установка и реальные проверки описаны
в [решении 14](../docs/Материалы/План_генератора_2026-10/14-full-connectome.md).

Для новой машины использовать [подготовку из первичных файлов](tools/connectome/README.md),
а не копирование чужого `.work`. Исходный численный runtime и отдельный контейнер
подготовки имеют разные закреплённые версии сериализатора. Условия зависимостей
и перенесённых файлов перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

План интеграции и проверок: [пакет генератора](../docs/Материалы/План_генератора_2026-10/README.md).

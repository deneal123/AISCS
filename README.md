# Generator

Изолированный численный сайдкар AISCS: полный зарегистрированный граф MaleCNS,
его локальная биофизическая проекция, мембранные токи и запись E1−REF через LFPy.
Прежняя локальная цепь сохраняется отдельным пресетом. Пользователи, очередь,
права доступа и постоянное хранилище принадлежат backend.

## Структура

| Каталог | Ответственность |
|---|---|
| `service/domain/` | Динамика, размещение контактов, признаки и порты адаптеров |
| `service/application/` | Генерация записи и независимое разбиение реализации классификатора |
| `service/infrastructure/` | NEURON, LFPy, экспорт, изолированный процесс и распознавание |
| `service/presentation/` | HTTP и CLI |
| `service/settings/` | Настройки, приватный токен и пути |
| `service/main.py` | Сборка зависимостей и фабрика приложения |
| `validation/demo-v1/` | Зафиксированные параметры классификатора, разбиение и результаты проверки |
| `validation/male-cns-v1/` | Отдельный замороженный протокол полной сети, 480 записей, ошибки и контрольные суммы |
| `tools/connectome/` | Закреплённый сборщик зарегистрированного графа из первичных файлов |
| `docker/`, `tests/` | Linux-сборка и численные/контрактные проверки |

Пакет использует собственный `uv.lock` и Linux Python 3.12. Имя `service` совпадает
с другими сайдкарами: запускать команды из этого проекта, не объединять Python paths.

## Запуск

Основной контур запускается из суперпроекта через `docker/build.sh --dev` и
`docker/run.sh --dev`. Приватный токен создаёт общий `docker/sync_env.py`.

Автономно в Linux:

```sh
uv sync --frozen
uv run generatorctl catalog
uv run generatorctl run --stimulus strong --seed 1 --output .work/example
uv run pytest -q
uv run ruff check service tests
```

Для независимой Linux-проверки из этого каталога:

```sh
docker build -f docker/Dockerfile --target test -t aiscs-generator-test:0.1.0 .
docker run --rm aiscs-generator-test:0.1.0
docker build -f docker/Dockerfile --target runtime -t aiscs-generator:0.1.0 .
```

Рабочий образ не содержит тестов, pytest и Ruff. Тестовый target использует то же
ядро и lock-файл; временные результаты записываются в `/work` или `/tmp`.

HTTP: `/health`, авторизованные `/ready`, `/capabilities`, `/v1/validate`,
`/v1/executions` и операции status/cancel/manifest/artifacts/ack/discard.
Передать `Authorization: Bearer <GENERATOR_TOKEN>`; секрет не включать в конфигурацию
опыта. Повтор ID с другой конфигурацией отклоняется. `ack` очищает промежуточные
файлы только после подтверждения хеша конфигурации; receipt сохраняется.

## Область применимости

Авторская цепь из шести клеток и общие HH-параметры не являются проверенной моделью
ноцицепции Drosophila. Геометрия мухи в frontend задаёт визуальный контекст.
Физический оператор предполагает бесконечный однородный изотропный проводник.
Токи — нА, время — мс, координаты — мкм, потенциал — мкВ.

Классификатор прежней локальной демонстрации различает три воздействия по сигналу.
Отложенная balanced accuracy — 2/3; слабое воздействие распознаётся недостаточно
устойчиво. Это вычислительная проверка на синтетических реализациях, без проверки
на животных или людях. Результаты и ошибки сохранены в `validation/demo-v1/`.

Пресет `male-cns-hybrid-v1` рассчитывает 166 700 нейронов и 25 582 938 связей;
линии рисунка используют LOD. Входы головы и ног подтверждены аннотациями, вход
брюшка недоступен. Периферические пути схематичны. Запись относится к шести HH-
источникам проекции, а не ко всей ЦНС. Отдельное распознавание полной модели имеет
balanced accuracy 71,875% на 96 отложенных записях из 32 конфигураций; полнота
слабого класса — 53,125%. Общий классификатор без области дал 72,917%:
преимущество регионального варианта не показано. Результаты, матрицы ошибок,
диапазоны применимости и повторная проверка — в `validation/male-cns-v1/`.
Данные не входят в образ/Git; отсутствие набора не подменяется локальной
моделью при запросе полного пресета. Команда `generatorctl connectome-verify`
проверяет все зарегистрированные хеши. Установка и реальные проверки описаны
в [решении 14](../docs/Материалы/План_генератора_2026-10/14-full-connectome.md).

Для новой машины использовать [подготовку из первичных файлов](tools/connectome/README.md),
а не копирование чужого `.work`. Исходный численный runtime и отдельный контейнер
подготовки имеют разные закреплённые версии сериализатора. Условия зависимостей
и перенесённых файлов перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

План интеграции и проверок: [пакет генератора](../docs/Материалы/План_генератора_2026-10/README.md).

## Подготовка ориентиров визуализации

Обзорные поверхности 114 областей нейропиля MaleCNS загружаются и проверяются
отдельно от исходного кода. Из каталога `generator`:

```bash
uv run python scripts/acquire_neuropil.py --output ../.data/male-cns/neuropil-v1
uv run python scripts/audit_neuropil.py --directory ../.data/male-cns/neuropil-v1 --output ../.work/neuropil-audit.json
uv run python scripts/export_neuropil_lod.py --source ../.data/male-cns/neuropil-v1 --output ../.data/male-cns/neuropil-lod-v1
```

Повторная загрузка сверяет существующие файлы с источником и не перезаписывает
несовпадающие данные. Экспорт создаёт новую генерацию и не перезаписывает её
манифест. Это визуальная аппроксимация сегментации; она не задаёт проводимость
тканей и не подтверждает точность совмещения с моделью тела.

Для нейронов без координат сомы/ориентира используются SWC того же MaleCNS v1.0,
по точному bodyId. Это отдельная подготовка сцены; она не меняет численное ядро.
Из каталога `generator` в Linux-окружении с зависимостями проекта:

```sh
uv run python scripts/make_scene_inventory.py --annotations /work/datasets/malecns-v1/graph/neurons.feather --output .work/morphology/inventory.json
uv run python scripts/prepare_scene_morphology.py --inventory .work/morphology/inventory.json --output .work/morphology/downloads
uv run python scripts/export_scene_morphology.py --inventory .work/morphology/inventory.json --source .work/morphology/downloads --target ../frontend/public/assets/simulator/malecns
```

Для инспекции синапсов используется отдельная [таблица MaleCNS v1.0](https://male-cns.janelia.org/download/)
`syn-partners-male-cns-v1.0-minconf-0.5.feather` (6 777 179 098 байт). Храните
её вне Git и Docker-образа. Для сборки индекса из корня суперпроекта, при уже
подготовленном графе в томе работающего `aspa-dev-generator-1`:

```sh
docker run --rm --volumes-from aspa-dev-generator-1:ro \
  -v "$PWD/generator:/src:ro" -v "$PWD/.data/male-cns/synapses:/output" \
  -w /src --entrypoint python aspa-generator:dev scripts/build_synapse_index.py \
  --source /output/syn-partners-male-cns-v1.0-minconf-0.5.feather \
  --graph /work/datasets/malecns-v1/graph --output /output/index-v1
```

Скрипт проверяет закреплённый манифест и ID графа, MD5 исходной таблицы,
затем атомарно публикует индекс. Существующий `index-v1` не перезаписывается.
В dev-профиле исходная таблица и индекс монтируются в generator только для
чтения; путь можно заменить переменной `GENERATOR_SYNAPSE_PATH`. Первая
проверка целостности при запросе может занять более минуты. Координаты имеют
единицу 8 нм и не подтверждают физическое совмещение ЦНС с телом.

Загрузчик возобновляется по проверенным хешам и делает не более двух попыток
на файл. Экспорт повторно сверяет каждый SWC, точный состав ID и выбранную вершину.
Публикуются компактные ориентиры и сжатые квитанции; первичные файлы остаются
в `.work/`. Получен полный охват 26 062 отсутствовавших ориентиров, без ошибок.
Ориентир на отростке не считается сомой или физическим источником регистрации.
Регистрация ЦНС относительно поверхности тела и оператор внешней стимуляции
остаются самостоятельными задачами.

Экспериментальный поиск по расстоянию до отростков использует отдельный снимок
границ SWC: `scripts/build_morphology_bounds.py` сверяет исходные файлы и
возобновляет построение SQLite-индекса. После завершения и независимой проверки
индекс можно подключить только для чтения и указать его путь внутри контейнера
в `GENERATOR_MORPHOLOGY_BOUNDS_DB`, а созданный независимым аудитом отчёт — в
`GENERATOR_MORPHOLOGY_BOUNDS_AUDIT`. Неполный или изменённый после аудита индекс
отклоняется. Запрос
`POST /v1/connectome/spatial-candidates` возвращает расстояния до осевых линий
сегментов в исходных координатах MaleCNS, а не вероятности возбуждения.
Кандидаты повторно сверяются с источниками; полнота относится к снимку и не
подтверждает неизменность источников, исключённых предварительным фильтром.
Независимый аудит `scripts/audit_morphology_bounds.py` принимает `--graph`,
повторяемый `--morphology-dir`, `--index`, `--report` и `--workers`. Отчёт
создаётся только после проверки всех источников и неизменности индекса; существующий
отчёт не перезаписывается.

Дополнительный сегментный R-tree строится `scripts/build_segment_index.py` из
проверенного индекса и независимо проверяется `scripts/audit_segment_index.py`.
После полного успешного аудита пути можно передать через
`GENERATOR_MORPHOLOGY_SEGMENT_DB` и `GENERATOR_MORPHOLOGY_SEGMENT_AUDIT` вместе.
При несовпадении хеша или неполном аудите поиск отказывает; если обе переменные
отсутствуют, используется проверенный индекс целых клеток. Сегментный индекс
является предварительным геометрическим фильтром и не оценивает возбуждение.
Полный индекс пока строится и не включён в действующий контур.

Экспериментальный `current_archive` сохраняет токи выбранных независимо
рассчитанных клеток и позволяет повторно вычислить дифференциальную запись при
других E1/REF без повторного решения их динамики. Каждый файл и манифест
проверяются по SHA-256; хеш манифеста должен поступать из доверенной записи
опыта. Внутренний `FieldGraphExecution.execute` может явно включить архив в
отдельном каталоге и проверяет восстановление исходной записи до возврата.
Архив пока не публикуется через API, очередь и постоянное хранилище и не
представляет собой запись всей сети или проверенную модель тканей.
Модуль `current_transport` подготавливает проверяемый ZIP для передачи и
восстанавливает только перечисленные манифестом файлы; подключение к
транспорту backend ещё не реализовано.

Для проверки исходной геометрии доступен защищённый внутренний запрос
`POST /v1/connectome/morphology/{body_id}/field`. Он принимает `source_um`,
`return_um`, `current_na`, `conductivity_s_m` и `clearance_um` в исходной системе
MaleCNS, проверяет SWC и возвращает потенциал и кривизну с хешем источника.
Это поле идеальных точечных контактов в однородной бесконечной среде; оно не
устанавливает активацию нейронов и не использует координаты поверхности flybody.
Backend предоставляет владельцу записи соответствующий расчёт в исходных
координатах; пользовательский интерфейс с этим запросом пока не связан.

Пакетный расчёт тех же сводок доступен через
`python scripts/compute_network_field.py --help`. По умолчанию используется CPU;
экспериментальный `--field-backend gpu` использует один GPU-процесс и может
подготавливать морфологии в отдельных CPU-процессах через `--workers 2`–`8`.
Порядок и проверка каждой реконструкции сохраняются. Отдельный
образ с CUDA-инструментами можно собрать и проверить при доступном NVIDIA GPU:

```sh
docker build -f docker/Dockerfile --target gpu-runtime -t aspa-generator:gpu .
docker run --rm --gpus all --entrypoint python aspa-generator:gpu -c 'from numba import cuda; print(cuda.is_available())'
```

Чтобы выполнить пакетный скрипт в этом образе, подключите каталог `generator`
только для чтения, а также проверенные данные и отдельный каталог результатов;
запустите `/src/scripts/compute_network_field.py` с `PYTHONPATH=/src`. Обычная
сборка без `--target` остаётся CPU-вариантом. Версии устройства и библиотек входят
в происхождение результата; недоступная GPU вызывает ошибку без подмены CPU.
На RTX 3060 локально проверены CUDA-ядро и подготовка поля для 128 реальных SWC:
GPU не показала устойчивого ускорения всей подготовки, хотя вычисление поля
миллиона искусственных точек с передачей данных было быстрее CPU. Результаты
хранятся в `.work/connectome-routing-20261028/*cuda*20261107*` суперпроекта.
Этот режим не ускоряет NEURON и не применяется автоматически в сервисе.
Для экспериментального полного сетевого прокси поле можно выбрать явно:
`GENERATOR_FIELD_BACKEND=gpu` и, например, `GENERATOR_FIELD_WORKERS=2` в окружении исполнителя
с доступной CUDA; по умолчанию используется CPU. Автономный `run_field_proxy.py`
при `--compute-field --field-backend gpu --field-workers 2` использует тот же
путь. Ошибка CUDA не подменяется расчётом на CPU. Это выбор оператора поля,
а не ускорение сетевой модели, NEURON или гарантия ускорения полного опыта.
Исполнитель, запущенный как daemon-процесс, вынужденно использует один процесс
подготовки: Python запрещает дочерние процессы внутри такого исполнителя.
В `metadata.json` сетевого результата раздел `field_execution` записывает запрос
на вычисление поля, выбранный backend и число процессов подготовки; при повторном
использовании сводки они не выдаются за параметры нового вычисления поля.
Развёртывание GPU-контура ещё не подтверждено.
Автономный `compute_network_field.py` также имеет экспериментальный режим
`--field-backend gpu-fused` с обязательным проверенным кэшем. Он объединяет
соседние пакеты, сохраняет прежний формат сводки и откатывается к действующему
оператору для неоднозначной геометрии и близких экстремумов. На полном графе
с удалённой парой контактов результаты совпали с CPU и прежним GPU-путём в
заданных допусках. Для одной конфигурации с контактами вблизи ЦНС два GPU-пути
также совпали; CPU-референс для неё ещё не проверен. Экспериментальный режим
доступен исполнителю при явном выборе `GENERATOR_FIELD_BACKEND=gpu-fused` и
наличии всех четырёх настроек проверенного кэша; автоматического перехода на CPU
нет. Полный автономный расчёт поля с удалёнными контактами занял 161,48 с и
совпал с CPU в допусках. Это не время полного опыта; подключение через контейнер
и интерфейс ещё не проверено.
Проверка расположения контактов использует отдельный пакетный разбор SWC. На
полном индексированном наборе для 37 точек совпали сводные числа пересечений;
подробные зазоры отдельно проверены на выборке. Проверка относится к снимку
реконструкций и не подтверждает поверхность тканей или возбуждение нейронов.
При полной конфигурации кэша исполнитель проверки контактов выбирает только
пакеты с кандидатами по проверенным пространственным индексам и проверяет их
хеши. Неиспользованные пакеты не читаются; неполный или повреждённый кэш даёт
ошибку. Без конфигурации сохраняется проверка исходных SWC. Выборочный путь
проверен автономно; контейнер и интерфейс не запускались.
Для будущего ускорения повторных запусков в `geometry_cache/` подготовлены
проверка полного аудированного индекса источников и ограниченный формат
двоичных пакетов морфологий без потери точности. Кодек требует независимо
проверенные хеши источников и доверенное описание пакета; он не подтверждает,
что исходный каталог SWC не изменился после аудита. Добавлены явное создание
снапшота со сжатием без потери точности и потоковое чтение пакетов с проверкой
отдельно сохранённого хеша манифеста. Автономный `scripts/build_geometry_cache.py` создаёт кэш только по
явной команде; `scripts/compute_network_field.py` принимает его в GPU-режиме
вместе с хешем манифеста, индексом и аудитом источников. Полный кэш построен;
его использование в действующем сервисе ещё предстоит проверить.
Для исполнителя предусмотрены настройки `GENERATOR_GEOMETRY_CACHE_DIR`,
`GENERATOR_GEOMETRY_CACHE_MANIFEST_SHA256`, `GENERATOR_GEOMETRY_SOURCE_INDEX`
и `GENERATOR_GEOMETRY_SOURCE_AUDIT`: все четыре задаёт администратор вместе
с `GENERATOR_FIELD_BACKEND=gpu`. Хеш манифеста хранится отдельно и проверяется
перед чтением. Без настроек действует прежний путь; частичная конфигурация
завершает запуск ошибкой. Реальное подключение и GPU-контейнер не проверены.
При аварийном завершении построения могут остаться незавершённые файлы;
частичный результат нельзя использовать.
Для двух завершённых сводок одинаковой конфигурации `scripts/compare_network_field.py`
проверяет обе цепочки и контрольные суммы файлов, затем сопоставляет статусы,
метаданные и экстремумы с заданными допусками. Сравнение экстремумов не заменяет
сопоставление всех сегментных значений и не подтверждает биологический ответ.

Для отдельной исследовательской проверки есть `python scripts/screen_stim_sources.py --help`.
Скрипт последовательно рассчитывает зарегистрированные морфологии при заданном
воздействии и при нулевом токе, сохраняя каждую строку в проверяемый JSONL.
Повторный запуск продолжает только совместимый журнал: фиксируются версия графа,
порядок ID, конфигурация, версии зависимостей и хеш алгоритма. Фоновые переходы,
отсутствие переходов и ошибки перечисляются отдельно. Отбор пока не подключён к
сетевому API; он не доказывает физиологическое возбуждение или место синаптического
выхода. Расчёт всех клеток может занять значительное время и место на диске.
Опция `--workers 1..4` использует отдельные процессы NEURON; их число сохраняется
в журнале, поэтому при возобновлении нужно указывать прежнее значение.
Экспериментальный `--field-coupling virtual_current` заменяет внеклеточный
механизм эквивалентными токами в узлах кабельной модели только при одном
компартменте на ребро и без записи мембранных токов. Он предназначен для
сравнительной проверки скорости и пока не разрешён для формирования входа сети;
основной режим остаётся `extracellular`.
Если образец напряжения находится в пределах 10⁻⁶ мВ от выбранного порога,
экспериментальный отбор повторяет соответствующий расчёт исходным решателем и
записывает число таких повторов. Эта эвристика не является доказанной верхней
границей численной ошибки для всех клеток и параметров.
`scripts/prepare_screened_graph.py --help` проверяет завершённый журнал именно
по всем ID зарегистрированного графа и подготавливает конфигурацию для отдельного
сетевого запуска. Он отказывает при отсутствующих данных, неоднозначном контроле,
изменении настроек, пустом выборе или пересечении клеток записи с источниками.
Сам запуск и передача журнала через backend этим скриптом не выполняются.

Для исследовательской проверки отдельной клетки доступен
`uv run python scripts/replay_registered_cell.py --help`. Скрипт принимает
зарегистрированный граф, проверенный индекс исходной таблицы синапсов, SWC,
завершённую запись сети и JSON настроек. Настройки содержат `body_id`,
`schedule` (задержка и параметры синапса), `simulation` (параметры решателя и
источника), `electrode_um`, `reference_um` и необязательный `source_model`.
Значения задаёт исследователь; параметры не считаются физиологически
калиброванными. Выходной каталог должен быть пустым: журнал и сигнал
сохраняются с манифестом и SHA-256, существующие файлы не перезаписываются.
Это одностороннее воспроизведение сохранённых LIF-событий в одной SWC-клетке,
без обратного влияния на сеть и без анатомической привязки к телу. Запуск
может быть длительным; скрипт показывает ход обработки страниц. К backend и
интерактивному интерфейсу он пока не подключён.

Моторный реестр для условной позы экспортируется отдельно, без изменения расчёта:

```sh
uv run python scripts/export_scene_motor.py --annotations /work/datasets/malecns-v1/graph/neurons.feather --target ../frontend/public/assets/simulator/malecns/motor.json
```

В нём 319 зарегистрированных клеток `vnc_motor` ножных нервов. Группирование
по стороне сомы не устанавливает сторону мышечной мишени. Реестр связывает
сохранённые LIF-события с условной позой; шесть HH-клеток оператора регистрации
не считаются моторной моделью.

Для новых запусков полного пресета каталог выбирает переднюю левую ногу и два
пассивных контакта на 25 мкм снаружи исходного дорсального меша. Происхождение
координат, нормалей и треугольников сохранено в
`service/domain/flybody-external-contacts.json`; эти данные включены в wheel.
Старые внутренние координаты остаются в сохранённых записях и в замороженном
протоколе классификатора. Его точность не относится к новым наружным положениям:
предсказание отклоняется как `outside_checked_domain`. Это не поле стимуляции
и не проверка проводимости тела. Ключ `thorax` исторически означает объединённый
тактильный вход шести ног, а не поверхность спины; новое значение по умолчанию
`front_left`. Физический STIM остаётся отдельной будущей задачей.

Для событийной подсветки схемы периферических нервов используется отдельный
экспорт, который сохраняет реальные положения клеток ЦНС:

```sh
uv run python scripts/export_peripheral_readout.py --annotations /work/datasets/malecns-v1/graph/neurons.feather --target ../frontend/public/assets/simulator/malecns/peripheral.json
```

Восьми областям сопоставлены 10 446 исходно аннотированных сенсорных и моторных
клеток. Брюшные внутренние клетки не выдаются за периферические. Это реестр
событий для схемы пучков, а не новая модель проведения, мышц или стимуляции.

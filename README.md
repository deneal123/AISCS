# Презентации диссертационного исследования

Два доклада автора — Данила Федоровича Вольхина — собираются из общего каталога `document/`:

- **PRES-001** — доклад к защите по постановке исследования и ИПР 2026–2030: 18 слайдов при лимите 20, из них два запасных для ответов на вопросы. Предобучение на Drosophila, перенос параметров и моделирование человеческого ECAP показаны раздельно; экспериментальное преимущество не заявляется.
- **PRES-002** — еженедельный отчёт научному руководителю о ходе работы над проектом и диссертацией, без лимита слайдов. Числа берутся из среза реестров соседних проектов.

## Запуск

Из `materials/presentation` либо из самостоятельного checkout ветки `presentation`:

```powershell
uv sync --frozen --extra dev
uv run --frozen presentationctl validate
uv run --frozen presentationctl build PRES-001 --profile draft
uv run --frozen presentationctl build PRES-002 --profile draft
```

Для инструментов нужен Python 3.12–3.13, для PDF — XeLaTeX и шрифты из [инструкции документа](document/README.md). Сервис устанавливается из исходного checkout; документ может собираться отдельно от Python и соседних проектов.

## Порядок работы

Слайды доклада к защите — в `document/slides/`, отчёта — в `document/progress/slides/`, общие параметры — в `document/config/`. Сохранять 4:3, согласованную типографику и подписи по предоставленному образцу. ГОСТ диссертации не устанавливает размеры шрифтов презентации. Назначение, регламент и устное сопровождение согласовываются отдельно.

Сверять тему, цель и шесть задач с ИПР и введением диссертации. Основания хранить в реестре и локальном снимке, на слайдах использовать обычные библиографические ссылки. Новые результаты добавлять только после соответствующих исследований. Лимит `max_slides` проверяется при валидации по числу кадров и после сборки по числу страниц.

## Еженедельный отчёт

1. Из `materials/presentation` суперпроекта (иначе указать `--workspace <корень>`): `uv run --frozen presentationctl progress-snapshot` показывает изменения без записи; с `--apply` обновляет `document/progress/generated/status.tex` и `data/progress-snapshot.json`. Окно коммитов задаётся `--since` (по умолчанию 7 дней), дата — `--as-of`.
2. Срез только читает реестры research, simulations, text, publications и presentation и журнал Git. Сгенерированный файл вручную не редактировать.
3. Переписать пункты слайдов «Итоги недели» и «План на следующую неделю», сверить заголовки-утверждения со свежими числами.
4. Собрать `presentationctl build PRES-002` и просмотреть все слайды. Коды задач показывать в колонках таблиц, в тексте — обычные названия.

## Проверки и выпуск

```powershell
.\scripts\check.ps1
```

Полная проверка включает структуру, Git-исключения, реестр, лимит слайдов, Ruff, pytest, draft-сборку обоих докладов и MCP smoke. `make check` запускает тот же набор; `make quick-check` пропускает сборку и MCP. Сервер `presentation-mcp` регистрируется как `aspa-presentation` через `scripts/install-codex-mcp.ps1`.

После содержательных правок проверить все слайды: читаемость, подписи, формулы, направление связей и отсутствие наложений. Успешная сборка обновляет PDF рядом с исходником; ошибка, проверочный запуск, превышение лимита и отказ release сохраняют прежний файл. Выпуск требует согласований и подтверждённых реквизитов.

## Локальные данные и история

`build/`, `.work/`, окружения, кэши и промежуточные файлы Beamer исключены из Git. Исходные рисунки, сгенерированный срез и PDF для просмотра сохраняются. `archive/` содержит неизменяемые снимки, `examples/` — прежний образец; они не задают научное содержание доклада.

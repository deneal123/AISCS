## Запуск

Из `materials/publications` либо из самостоятельного checkout ветки `publications`:

```powershell
uv sync --frozen --extra dev
uv run --frozen pubctl validate
uv run --frozen pubctl list
uv run --frozen pubctl build PUB-TEMPLATE-001 --profile draft
```

Инструменты требуют Python 3.12–3.13; PDF — XeLaTeX. Word/DOC/PDF-экспорт использует отдельный генератор конкретной статьи и установленный редактор. Сервис устанавливается из исходного checkout. Для автономной сборки переносится каталог конкретного материала с его инструкцией.

## Порядок работы

`PUB-002` — общий методологический обзор; `PUB-003` — обзор предпосылок коннектомного предобучения для ECAP. Их тексты, доказательства, журнальные профили и генераторы находятся в собственных каталогах. Различие между текущим профилем оформления и площадкой перспективного ИПР проверяется перед подачей; в этом проходе рукописи не переоформляются.

`PUB-001` защищён как неизменяемая версия подачи со статусом `submitted` в локальном реестре. По сообщению автора работа опубликована; окончательные выходные данные ещё требуется зарегистрировать. Защищённые файлы и статус снимка не меняются без установленной процедуры. Постер хранится отдельно и не изменяет статью.

Новую работу создавать с новым ID, например `pubctl new PUB-004 article-slug "Рабочее название" --kind paper --apply`. Перед этим проверить свободный ID через `pubctl list`. Доказательства импортируются явно в локальный снимок; сборка не читает соседний research автоматически.

## Проверки и выпуск

```powershell
.\scripts\check.ps1
```

Полная проверка включает структуру, Git-исключения, реестр и неизменяемые файлы, Ruff, pytest, draft-сборку шаблона и MCP smoke. `make check` запускает тот же набор; `make quick-check` пропускает сборку и MCP. Сервер `publications-mcp` регистрируется как `aspa-publications` через `scripts/install-codex-mcp.ps1`.

Сборка шаблона не проверяет оформление обеих статей или постера: для них применяются собственные сборщики и аудиты. Подача, изменение статуса и выпуск требуют подтверждений и согласований. Доступность `release` или `package` не означает разрешения отправлять материалы.

## Локальные данные и история

`build/`, `.work/`, окружения, временные файлы TeX и Word исключены из Git. Принятые PDF, исходные иллюстрации и печатный постер сохраняются. В `examples/legacy/` отделены прежние работы; однозначные временные файлы их сборки больше не отслеживаются. Уже зафиксированные архивные снимки сохраняются побайтово, включая их исторический состав.

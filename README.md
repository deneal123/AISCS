# agents — сайдкар агентного движка GPTHub

Отдельный сервис, исполняющий агентский слой платформы: мультипровайдерный LLM-слой,
роутинг, планирование, субагенты, инструменты, гардрейлы, сборка контекста, стриминг.
Раньше всё это было зарыто в бизнес-логику `backend`, что мешало разрабатывать и
масштабировать движок независимо. Долгоживущий процесс попутно убирает celery
loop-per-task хазард, который тут регулярно ломал модульные async-примитивы.

Подключается как сабмодуль (orphan-ветка `agents` того же репозитория GPTHub, как
`memos`/`ldr`/`duckdb`/`graphify`/`opendataloader`/`whisper`).

## Статус

**Боевой трафик идёт через сайдкар.** `AGENTS__ENGINE_MODE=http`, домен агентов из
backend УДАЛЁН — in-process пути больше нет, и сайдкар является единственным
исполнителем. Он же владеет провайдерами: все LLM-вызовы платформы, включая
OpenAI-совместимый шлюз `/v1` для memos/ldr/graphify, идут через него.

Состояния backend'а (PG/Redis/MinIO) у сайдкара нет по устройству. История, память,
резюме и ссылки на файлы приезжают В ТЕЛЕ `/run`, которое backend собирает сам;
табличные файлы — презайнед-ссылками, поэтому доступ к хранилищу не нужен.

Тем же путём приезжают две вещи, которые иначе молча деградировали бы:

* **`provider_policy`** — кого админ выключил чекбоксом, кого заблокировала
  health-проверка. Без снимка сайдкар считал бы, что запрещённых нет, и снятый админом
  провайдер снова принимал бы трафик. Различие значимо: снимка НЕТ → читаем свой
  источник; снимок ПУСТ → это ответ «никто не выключен».
* **`agent_settings`** — тумблеры инструментов, ретраи, лимиты контекста, порядок
  фейловера. Overlay живёт в БД backend'а; без слепка выключенный админом инструмент
  включился бы обратно. В слепке только ПЕРЕОПРЕДЕЛЁННОЕ, остальное — свой конфиг.

Оба снимка ещё и **запоминаются на процесс** — ради `/v1`: его зовут по OpenAI-протоколу,
где поля под политику нет, так что своего снимка у шлюза быть не может. Чат-трафик идёт
постоянно, поэтому память освежается сама. ⚠️ **Граница:** пока сайдкар не обслужил ни
одного `/run`, политика ему НЕИЗВЕСТНА и `/v1` работает по-старому. Это видно в
`/health.provider_policy` (`known: false`), а не молчит.

**Откат** (аварийный): `AGENTS__ENGINE_MODE=inprocess` потребует вернуть домен в
backend — то есть в норме не используется. `AGENTS__ENGINE_CANARY_USER_IDS` (CSV)
пускает перечисленных пользователей в сайдкар даже при `inprocess`.

## Структура

Раскладка та же, что у backend: `docker/` со сборкой, весь код одним каталогом,
`tests/` рядом. Пакет зовётся `service` — ровно как у backend. Раньше он звался `gpthub_agents`,
потому что кросс-сервисные тесты грузили оба пакета в один интерпретатор и
одноимённые столкнулись бы. Эти тесты переехали сюда и backend больше не
импортируют, так что препятствие снято, а имя стало общим для всех сервисов.

```text
docker/                 Dockerfile и entrypoint.sh
service/                ВЕСЬ код сервиса — один каталог, как у backend
  main.py                 сборка приложения (~50 строк)
  api/                    HTTP-слой, разрезанный по потребителям
    health.py               /health — хелсчек compose + контракт для сверки с backend
    run.py                  /run — главная ручка, стрим движка (зовёт воркер)
    route.py                /route — роутинг до диспатча (зовёт веб-процесс)
    catalog.py              /catalog* — метаданные и список чат-моделей
    providers.py            /providers/* — здоровье и ключи (админка)
    tools.py                /tools/* — инструменты движка как ручки (backend-UI)
    media.py                /media/* — провайдерские vision и STT
    vector.py               /vector/* — документы пользователя в Qdrant
    runtime.py              загрузка движка НА СТАРТЕ и ответ «что доступно»
    deps.py                 общие зависимости (авторизация внутренних ручек)
  application/ domain/ infrastructure/ presentation/   сам движок
  settings/               конфигурация сайдкара (только то, что он читает):
                          providers · sidecars · pipeline, класс AgentsConfig один
tests/                  контракт HTTP-слоя и поведение движка
```

Раньше код лежал ТРЕМЯ кусками в корне (`app.py`, `api/`, `gpthub_agents/`), и каждый
надо было не забыть в `COPY` — у тонких сайдкаров ровно так и потерялся `core.py`,
и три образа из четырёх собирались неработающими. Один каталог убирает этот класс.

Загрузка движка собрана в `api/runtime.py` — единственное место, отвечающее «что
доступно». Раньше каждая ручка импортировала своё под широким `except`, и отсутствие
модуля превращалось в тихую деградацию вместо видимой ошибки: так однажды `POST /route`
несколько выкладок отдавал 503 на каждый запрос, а backend это проглатывал.

## HTTP-контракт

| Эндпоинт | Назначение | Кто зовёт |
|---|---|---|
| `GET /health` | Хелсчек compose + готовность движка/шлюза/роутинга + контракт для сверки | compose, тест паритета backend |
| `POST /run` | Полный прогон движка: NDJSON-стрим `AgentEvent` + терминальный `__result__`/`__error__`. Тело = `AgentRunInput` | celery-воркер (`HttpAgentEngine`) |
| `POST /route` | Роутинг-решение до диспатча. ⚠️ `routing_usage` — токены роутер-ЛЛМ, по ним воркер тарифицирует ОТДЕЛЬНО | web-процесс |
| `/v1/*` | OpenAI-совместимый LLM-шлюз (chat/completions, models, embeddings) | memos/ldr/graphify |
| `GET /catalog` | Каталог моделей: окна контекста + возможности (без цен) | billing, пикер моделей |
| `GET /catalog/chat-models` | Список chat-совместимых id + владелец-провайдер. `?chat_only=true` отсекает эмбеддеры | billing, пикер моделей |
| `GET /providers/health` | Здоровье провайдеров глазами сайдкара (проба + политика). `?force=true` — как кнопка «Проверить» | admin |
| `POST /providers/keys` | Снимок провайдерских ключей от backend (замена ключа в панели). Защищён ключом шлюза | admin |
| `POST /tools/{web-search,parse-url,pptx}` | Инструменты движка как ручки. Не дублируются у backend намеренно: у `parse_url` внутри SSRF-гард, у `pptx` — ЛЛМ-вызов | backend-UI |
| `POST /media/{describe-image,transcribe}` | Провайдерские vision и STT. Локальный whisper остаётся у backend — он провайдеров не требует | backend |
| `POST /vector/{index,search,delete}` | Векторная база (Qdrant): документы пользователя. Защищены ключом шлюза | upload, graph_api |

## Общий код

**Его нет, и это решение, а не упущение.** Пакет `gpthub_core` ликвидирован —
сабмодуля `core` в `.gitmodules` не существует. Общий пакет означал бы согласованный
релиз двух сервисов при каждой правке контракта, то есть ровно ту связанность, ради
устранения которой движок и выносили.

То, что обязано совпадать у обеих сторон, **раздвоено осознанно**: контракт событий и
тело `/run` живут здесь (провайдер публикует — потребитель сверяет), а капабилити
вроде оценки токенов и SSRF-гарда имеют по копии у каждого сервиса плюс **общие
тест-векторы**, сверяемые в CI суперпроекта побайтово. Расхождение падает громко, в
момент правки, не связывая релизы.

Оценка токенов в этом списке не случайно: по ней воркер резервирует кредиты, а движок
режет контекст — разошедшиеся копии врали бы в чью-то пользу.

Клиенты соседних сервисов, наоборот, у каждого свои: общий клиент означал бы, что
изменение API соседа требует согласованного релиза обоих сервисов.

Раздвоение оставляет возможность расхождения контракта, а ломается при этом денежный
путь. Поэтому `/health` отдаёт контракт ИМЕНАМИ, backend сверяет их тестом
(`test_contract_parity_with_sidecar.py`), а в CI работает офлайн-сверка
(`scripts/check_contract_parity.py`) — она, в отличие от теста, не пропускается при
отсутствии поднятого сайдкара.

## Запуск (локально)

```sh
docker build -t gpthub-agents-sidecar -f docker/Dockerfile .
docker run --rm -p 8090:8090 gpthub-agents-sidecar
curl localhost:8090/health   # {"status":"ok","service":"agents",...}
```

Контекст сборки — сам каталог `agents/`. (Раньше здесь стояло «корень суперпроекта,
образу нужен ещё и `gpthub_core`» — неверно уже дважды: общего пакета нет, а Dockerfile
копирует только `pyproject.toml`, `uv.lock`, `service/` и `docker/entrypoint.sh`.)

## Тесты

Покрывают HTTP-контракт, на который опирается backend (порядок событий в NDJSON-потоке,
терминальные `__result__`/`__error__` — из результата воркер СПИСЫВАЕТ ДЕНЬГИ, 503 при
недоступном движке) и поведение самого движка.

`pytest` намеренно НЕ кладём в образ — в проде он не нужен, ставим на время прогона:

```sh
docker exec gpthub-dev-agents-1 pip install -q pytest pytest-asyncio
docker cp tests gpthub-dev-agents-1:/opt/agents-sidecar/tests
docker exec -w /opt/agents-sidecar gpthub-dev-agents-1 python -m pytest tests -q
```

⚠️ Патчить в тестах нужно ПЕРВОИСТОЧНИК (`api.runtime`, `service.*`), а не модуль
`app`, который лишь собирает роутеры: иначе патч до кода не долетает и зелёный цвет
получается случайным.

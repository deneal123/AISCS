Каждый проект остаётся отдельным Git-сабмодулем со своим окружением, реестром, CLI и MCP. Команды из README выполняются из каталога соответствующего проекта.

## Общая структура

`README.md` — точка входа, `TODO.md` — открытые и выполненные критерии, `SKILL.md` — инструкция работы. `pyproject.toml` и `uv.lock` задают пакет и зависимости; `sidecar.json` связывает сервис с реестром и разрешёнными исходниками.

Во всех проектах `data/` содержит реестр и доказательства, `docs/` — план и аудиты, `service/` — CLI/MCP, `scripts/` — повторяемые операции, `tests/` — проверки. Для одного документа используется `document/`, для нескольких публикаций — `documents/` и `posters/`. `archive/` хранит неизменяемую историю, `examples/` отделяет сторонние образцы.

## Единый порядок работы

1. Сверить TODO, реестр и нужный исходник; сохранять фактические статусы и ограничения.
2. Редактировать текст вместе с его генератором и доказательными привязками, когда они затронуты.
3. Выполнить `scripts/check.ps1` или `make check`: структура, Git-исключения, реестр, Ruff, pytest, draft и MCP. `make quick-check` пропускает сборку и MCP.
4. После изменения вёрстки открыть результат и проверить соответствующие страницы. Техническая сборка не заменяет содержательное рассмотрение.
5. Обновить конкретный критерий TODO по доказательству. Выпуск и подача требуют предусмотренных согласований.

Окружения, `.work/`, `build/`, кэши и временные файлы TeX/Word исключены из Git. PDF для просмотра и исходные иллюстрации остаются материалами проекта. Исторические файлы допускаются в архиве только как часть зафиксированного манифеста; архивы не переписываются ради уборки.
